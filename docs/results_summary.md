# PU-GIB: сводка результатов (синтетика и LastFM на Mac, проверки Douban на кластере)

Состояние на 25.10.2026. Все числа — test NDCG@20 в контрольной точке, лучшей по валидационному NDCG@20,
если не сказано иное. «Δ» — парная разность внутри одного сида. Подробные таблицы — в `results/*_report.md`.

**Общий протокол.** Тёплый старт от лучшего чекпоинта LightGCN; lr = 1e-4 для эмбеддингов, 1e-3 для маски;
фиксированный бюджет 300 эпох, τ отжигается 1.0 → 0.2 за весь бюджет; L2 = 1e-4. Социальная форма — `gbsr`:
одна общая матрица смежности [[S, R], [Rᵀ, 0]], нормированная D^-½ A D^-½, у пользователя d_u = d^I_u + d^S_u.
Глобальный социальный вес ω умножает все социальные элементы поверх маски.

## 1. Главное в одном абзаце

На синтетике с известным истинным графом все механизмы PU-GIB работают как задумано. Оценщик ошибается в
предсказанную сторону, маска почти идеально отделяет ложные наблюдаемые связи (AUROC 0.95 против 0.60 у
GBSR), пул находит скрытые истинные связи. Но в этом мире **нечего выигрывать по NDCG**. Даже оракульный
денойзинг даёт +0.001, дополнение графа через пул — до +0.002 (+0.004 в отдельном канале), а равномерное
усиление соцканала (ω = 1.5) даёт больше любого из них. Выигрыш нашего порта GBSR на синтетике целиком
объясняется этим усилением. При подобранном ω все методы равны (≈ 0.150). На LastFM социальный граф не даёт
ничего ни одному методу. Значит, синтетику в статье используем как **проверку механизмов**, а выигрыш по
качеству ищем на Douban. Там официальный GBSR воспроизводит статью (N@20 0.1532 против 0.1523), и выигрыш
(+0.029 к варианту без HSIC) идёт от регуляризатора HSIC, а не от маски.

## 2. Синтетический мир

`scripts/make_synthetic.py`:
- 2000 пользователей и 2000 предметов, вкусовые векторы размерности 16; ~30 взаимодействий на пользователя
  выбираются с вероятностью ∝ exp(u·i / 0.1);
- истинный граф Z: 10 ближайших по вкусу на пользователя, симметризованный (~11.7k связей);
- наблюдаемый граф A: каждая связь Z сохраняется с c = 0.5, плюс равномерно случайные ложные связи —
  20% наблюдаемых;
- протокол как на реальных данных: 80/10/10 по пользователю, 10% социальных связей отложено.

Сиды 0/1/2 — три независимых мира. Свойство, важное для интерпретации: случайные ложные связи почти не
попадают в Ω (двухшаговую вселенную). Из 1326 ложных обучающих связей в Ω лежат 27. Поэтому оценщик видит
почти чистый канал, а маска работает со всеми наблюдаемыми связями.

## 4. Механизмы (для статьи — основная роль синтетики)

### 4.1 Оценщик канала на Ω (κ = 0.02, 3 сида)

| | истина | EN (Элкан–Ното с поправкой) | anchor (кросс-фит) |
|---|---|---|---|
| c | 0.454 ± 0.013 | 0.141 ± 0.012 | 0.221 ± 0.011 |
| π | 0.072 ± 0.003 | 0.233 ± 0.009 | 0.147 ± 0.003 |
| ρ_obs | 0.981 ± 0.002 | 0.985 ± 0.000 | 0.983 ± 0.000 |
| ρ_un | 0.041 ± 0.002 | 0.207 ± 0.010 | 0.119 ± 0.003 |

Ошибка всегда «разрешительная» (ĉ ≤ c, приоры ≥ истинных), как предсказывает Утверждение 3.1. Anchor вдвое
сокращает ошибку по ρ_un и π. При κ > κ* (0.05, 0.1) граница для ρ_obs нарушается — ровно предупреждение
Утверждения. κ* = 0.018–0.022 по сидам.

### 4.2 Маска (AUROC α для истинных против ложных наблюдаемых связей, 3 сида)

| модель | AUROC | α истинные / ложные (сид 0) |
|---|---|---|
| PU-GIB без кандидатов, β = 0.001 | **0.954 ± 0.003** | 1.000 / 0.833 |
| PU-GIB, пул K = 10, β = 0.01 | 0.908 ± 0.029 | 0.996 / 0.976 |
| GBSR (наш порт, с градиентом в маску) | 0.599 ± 0.006 | 0.996 / 0.936 |

При β = 0.01 приор доминирует (ложные связи α ≈ 0.98), но порядок связей сохраняется. При β = 0.001
маска отделяет ложные связи по-настоящему.

### 4.3 Пулы кандидатов (3 сида)

| пул | K | точность (доля из Z) | доля вне Ω | доля найденных недостающих связей Z |
|---|---|---|---|---|
| двухшаговый (s) | 5 / 10 / 20 | 0.19 / 0.12 / 0.07 | 0 | 0.19 / 0.23 / 0.25 |
| глобальный (s по всем парам) | 5 / 10 / 20 | 0.26 / 0.20 / 0.14 | 0.83–0.87 | 0.26 / 0.38 / 0.52 |
| RA (двухшаговый, K = 10, сид 0) | 10 | — | 0 | 0.45 скрытых в Ω против 0.91 у s |

Двухшаговый пул упирается в ~25%: остальные недостающие связи лежат вне Ω. На синтетике ранжирование по s
сильнее RA. На LastFM было наоборот (RA 0.31 против s 0.20 по отложенным связям) — это стоит отметить.

## 5. Сколько вообще можно выиграть на синтетике

Парные Δ к LightGCN-S на A, 3 сида (mean ± std):

| вариант | ω = 1 | ω = 1.5 |
|---|---|---|
| LightGCN (без соцграфа) | −0.0068 ± 0.0003 | — |
| все соцвеса ×1.48 (= средний вес GBSR) | +0.0025 ± 0.0005 | — |
| GBSR | +0.0030 ± 0.0005 | +0.0003 (к LightGCN-S при ω = 1.5) |
| потолок денойзинга (A ∩ Z) | +0.0011 ± 0.0009 | +0.0009 |
| оракул Z | +0.0066 ± 0.0014 | +0.0091 |
| потолок дополнения, двухшаговый K = 20 (A + истинные из пула) | — | +0.0021 ± 0.0006 |
| потолок дополнения, глобальный K = 20 | — | +0.0023 ± 0.0011 |
| то же в отдельном канале, ω_c = 0.25 | — | **+0.0040 ± 0.0019** |
| PU-GIB без кандидатов | +0.0000 ± 0.0004 | +0.0004 |
| PU-GIB K = 10 | +0.0005 ± 0.0009 | +0.0004 |
| LightGCN-PU K = 10 | −0.0001 ± 0.0013 | — |

Выбор ω по валидации на сиде 0: ω = 1.5 для всех пяти методов (сетка {0.5, 1, 1.5}). При ω = 1.5
(3 сида): LightGCN-S 0.1502 ± 0.0057, GBSR 0.1504 ± 0.0055, PU-GIB без кандидатов 0.1504 ± 0.0061,
PU-GIB K = 10 0.1500 ± 0.0058, LightGCN-PU 0.1492 ± 0.0058, потолок денойзинга 0.1510 ± 0.0064.

Выводы:
1. **Потолки малы.** Денойзинг ≤ +0.001, дополнение ≤ +0.002 (+0.004 в отдельном канале). Синтетика не может
   показать выигрыш по NDCG ни для какого метода очистки или дополнения.
2. **Вес соцканала — скрытый гиперпараметр.** Гейт GBSR (σ(·) + 0.5, среднее ≈ 1.48) равномерно *усиливает*
   соцканал. Это объясняет весь выигрыш GBSR на синтетике. Честное сравнение требует подбирать ω у LightGCN-S.
3. Оракул Z выигрывает за счёт полноты: большинство его дополнительных связей лежит вне Ω.

## 6. Добавление кандидатов (синтетика, ω = 1.5, Δ к LightGCN-S на A, 3 сида)

| граф | совместная форма | отдельный канал ω_c = 0.25 | ω_c = 0.5 | ω_c = 1 |
|---|---|---|---|---|
| потолок: A + истинные из глобального K = 20 | +0.0023 | **+0.0040** | +0.0029 | −0.0041 |
| жёстко: A + весь глобальный K = 20 (как SHaRe) | −0.0094 | **−0.0015** | −0.0035 | −0.0099 |
| жёстко: A + весь двухшаговый K = 5 / 10 / 20 | −0.0010 / −0.0010 / −0.0001 | | | |
| адресно (степень ≤ 2, глобальный K = 10), потолок | −0.0003 | −0.0004 | −0.0008 | −0.0025 |
| адресно, жёстко | −0.0001 | −0.0007 | −0.0020 | −0.0079 |

- Жёсткое добавление по сходству вредит, причём сильнее для дальних (глобальных) кандидатов, хотя они точнее.
  Аргумент в пользу отбора по маске, а не правила «топ-M».
- Отдельный канал (своя нормировка по степеням кандидатов, свой вес) убирает большую часть вреда: кандидаты
  больше не размывают нормировку основного графа. Вес должен быть малым: при ω_c = 1 вредят даже одни
  истинные связи.
- Адресное добавление затрагивает ~2% пользователей (34–46 из 2000). В целом ≈ 0, в целевой группе скорее вредит.

## 8. LastFM в целом

- Социальный граф ничего не даёт: LightGCN-S 0.2360 ≈ LightGCN 0.2365 (форма `gbsr`, сид 0); на трёх сидах в
  нашей форме было то же.
- Шум не вредит: +40% случайных связей в Ω снижают NDCG@20 на 0.0004 (3 сида). LastFM не может показать
  эффект денойзинга.
- GBSR в форме `gbsr` хуже: 0.2325 против 0.2360 у LightGCN-S.
- Механизм работает: оракул test–train даёт +0.022 (0.2586).
- Выводы шага 3 (наша форма, без подбора ω): все варианты PU-GIB ≈ LightGCN-S с тем же тёплым стартом; при
  β ≥ 0.01 α копирует приор; без приора (β = 0) BPR сам опускает веса наблюдаемых связей до ≈ 0.06.

## 9. Проверки реализации (Douban-Book, сид 0, кластер)

**Оракульный тест, обученный** (Δ к LightGCN warm 0.1062):

| | наша форма (ω_S = 0.5) | форма `gbsr` |
|---|---|---|
| реальный граф | −0.0018 (0.1044) | **+0.0012 (0.1074)** |
| оракул test–test | +0.0268 (0.1330) | +0.0158 (0.1220) |
| оракул test–train | +0.0426 (0.1488) | +0.0288 (0.1350) |

Социальный канал работает в обеих формах. Вывод замороженной проверки («наша форма сломана») был ошибочным:
необученные эмбеддинги просто не были приспособлены к соцграфу. Наша форма сильнее усиливает соцсигнал —
выгодно на чистом графе, вредно на шумном. Переход на `gbsr` оправдан результатом на реальном графе; корректнее
подбирать ω для обеих форм. Большинство запусков достигают лучшего результата на эпохах 280–300, то есть
бюджета 300 для Douban мало.

**Официальный код GBSR** (без изменений, собственный сплит Douban-Book 80/20, выбор эпохи по тесту, 1 сид):

| | R@10 | N@10 | R@20 | N@20 | лучшая эпоха |
|---|---|---|---|---|---|
| GBSR, β = 40, σ = 2.5 | 0.1194 | 0.1461 | 0.1710 | **0.1532** | 51 |
| тот же код, β = 0 (без HSIC) | 0.0999 | 0.1161 | 0.1473 | **0.1246** | 356 |
| статья: GBSR | 0.1189 | 0.1451 | 0.1694 | 0.1523 | — |
| статья: LightGCN-S | 0.1021 | 0.1187 | 0.1506 | 0.1281 | — |

Код воспроизводит статью. Выигрыш (+0.029) даёт HSIC, а не маска: в официальном коде на маску не идёт
градиент (`torch_version/GBSR.py`, строка 68), и случайный гейт есть и при β = 0. Модель выбирается по тесту
(`rec_dataset.py`, строка 71; `torch_version/run_GBSR.py`, строки 134–136). Наш порт этот выигрыш пока не
воспроизвёл (0.0979 на старом расписании). Расхождения: тёплый старт с малым lr, градиент в маску, протокол.

## 10. Открытые вопросы

1. Воспроизводит ли наш порт GBSR 0.153 на их сплите с их настройками (холодный старт, `detach_mask: true`,
   lr 1e-3)? Если да — расписание с тёплым стартом мешает HSIC (и, возможно, PU-GIB).
2. Бюджет для Douban: 300 эпох мало; нужно 600 эпох или больший lr_emb.
3. Подбор ω для LightGCN-S и всех социальных методов на Douban (обязателен после §5).
4. Группы пользователей на Douban: нужны перезапуски с поюзерными метриками.
5. Ранжирование кандидатов: на синтетике s сильнее RA, на LastFM наоборот.
